# 功能规格（spec）

- 状态：现行
- 维护者：项目所有者
- 最后更新：2026-09-04

本目录定义每个功能的**行为**：做什么、是否正确。与 `docs/ux/` 的分工：spec 管"正确"，ux 管"好用"。

## 命名与编号

- 文件名：`NNNN-功能-slug.md`（如 `0001-import.md`）
- 编号与体验规格**同号对应**：`spec/0001-import.md` ↔ `ux/0001-import.md`
- 模板：`_template.md`

## 状态矩阵（必须覆盖七状态）

每份规格必须为所涉流程填写状态矩阵，每状态写明：展示什么 / 用户能做什么 / 文案要点 / 错误码。

| 状态 | 含义 |
| :--- | :--- |
| 空 | 无数据可展示（首次使用、全部删除） |
| 加载中 | 操作进行中，需可见进度或骨架 |
| 成功 | 正常完成 |
| 部分成功 | 批量操作有失败项（如导入含坏文件） |
| 错误 | 操作失败，给出"发生了什么 + 能做什么" |
| 离线 | 模型未下载/网络不可用时的降级说明 |
| 权限缺失 | 无目录读取权限等（桌面端常见） |

## 验收标准写法

- Given / When / Then；每条必须可测（单测或 e2e）。
- 性能类指标**引用** `docs/ux/latency-budget.md`，不重复定义。
- 评审后冻结验收标准；实现期间修改需重新评审。
