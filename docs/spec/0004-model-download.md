# 规格 0004：模型下载

- 状态：已评审（2026-09-06 修订：触发时机由"首次搜索"前移至"启动自动"，所有者质询确认）
- 负责人：ZCode（AI 代理）
- 关联切片：P2（ADR-0007）
- 关联体验规格：`docs/ux/0004-model-download.md`
- 关联 ADR：ADR-0006、ADR-0010
- 关联规格：spec 0008（推理运行时分发复用本规格下载器模式）
- 最后更新：2026-09-06

## 1. 目标与非目标

**目标**：应用启动即检查模型资产（Chinese-CLIP ViT-B/16 的视觉/文本 ONNX、词表、清单）是否齐全；缺失时**自动开始后台下载**（导入索引与搜索共用这一套模型，视觉塔建索引、文本塔编码查询），支持断点续传与校验，全程进度可见。

**修订原因（2026-09-06）**：原设计把下载引导挂在搜索流程里，但模型从第一次导入就是必需品——没有视觉塔，图片向量永远无法生成，后台嵌入线程一直空转。把关键前置条件藏到最后一环是设计错误。

**非目标**：模型自动更新（版本随应用锁定，ADR-0006）；多模型管理；P2P/CDN 分发（LATER，可配置分发源预留）。推理运行时（onnxruntime 变体）的分发不在本规格，见 spec 0008（复用本规格的下载器模式）。

## 2. 用户故事

作为用户，我装好应用后什么都不用点，模型就在后台自己准备；我清楚地知道下载的是什么、多大、多久，断网后能接着下，以便放心等待。

## 3. 流程

1. **触发（修订）**：应用启动检查 `model_status`，清单文件缺失（或就绪但未加载）→ 自动调用 `download_models`（幂等，下载中重复调用直接返回）；搜索离线态的「下载语义模型」按钮保留为**失败重试/手动入口**。
2. 读取内置清单（`manifest.json`：文件名、SHA-256、字节数、版本）；逐文件检查本地模型目录（命中校验则跳过）。
3. 下载：主源 + 备源（默认 GitHub Releases 托管；`config.toml` 的分发源可整体替换，预留 HF/魔搭）；HTTP Range 断点续传（临时 `.part` 文件，完成后校验改名）。
4. SHA-256 校验失败：删除重下（最多 3 次），仍失败进错误态。
5. 全部就绪：模型加载完成广播 `model-ready`，嵌入线程自动开始补建索引，搜索立即可用。

## 4. 状态矩阵

| 状态 | 展示什么 | 用户能做什么 | 文案要点 | 错误码 |
| :--- | :--- | :--- | :--- | :--- |
| 空（待触发/失败待重试） | 搜索框离线态引导 | 手动触发/重试下载 | "导入索引与搜索需要一套中文图文语义模型（约 200MB，仅一次）" | model_missing |
| 加载中 | 总进度 + 当前文件名 + 断点续传提示（**空态与浏览态全局可见，不要求先点搜索**） | 后台等待、继续用导入/浏览 | "正在下载语义模型 128MB / 200MB（已下载部分不会丢失）" | - |
| 成功 | 嵌入进度接管（"还有 N 张照片正在建立索引"） | 直接搜索 | "模型就绪，试试搜索你的照片" | - |
| 部分成功 | 不适用（必须全部就绪才可用） | - | - | - |
| 错误 | 错误提示 + 重试入口（搜索框引导块） | 重试、查看网络提示 | "下载失败：网络不可用。已下载的部分会保留，恢复网络后接着下" | model_download_failed |
| 离线 | 同错误（网络不可达场景） | 稍后重试 | 同上 | model_download_failed |
| 权限缺失 | 写入失败提示 | 以正常权限重装应用 | "模型目录无法写入" | write_failed |

## 5. 数据契约

- 清单（`mm-embed` 内置 `include_str!`）：`ModelManifest { version, files: Vec<ModelFile { name, sha256, size }> }`
- 事件：`model-download-progress { file, received, total }`（复用导入进度 UI 模式）
- 命令：`download_models() -> ()`（异步任务 + 事件）、`model_status() -> ModelStatus`
- 存储：`{模型目录}/{清单文件名}`；模型目录默认 `AppData/MiaoMory/models`（`mm-platform` 已解析，可配置）

## 6. 验收标准（Given / When / Then）

1. Given 首次启动且模型缺失，When 应用启动完成，Then **未做任何点击**即开始下载且进度可见。
2. Given 清单 3 个文件全缺失，When download_models，Then 全部下载且 SHA-256 校验通过，model_status=ready。
3. Given 某文件已存在且哈希匹配，When 下载，Then 该文件被跳过（不重复下载）。
4. Given 下载中断（进程被杀），When 再次 download_models，Then 从 `.part` 断点继续。
5. Given 文件被篡改（哈希不符），When 下载，Then 重下；3 次失败后进入错误态（文案含"已下载部分会保留"）。
6. Given 配置了不可达分发源，When 下载，Then 错误态且错误码 model_download_failed。
7. Given 自动下载进行中，When 用户再点「下载语义模型」，Then 幂等返回，不产生第二个下载任务。

## 7. 边界与降级

- 磁盘满：write_failed 文案；清理 `.part` 后可重试。
- 代理环境：跟随系统代理（reqwest 默认）。
- 清单版本与模型不匹配（应用升级换模型）：清单内版本字段不一致时提示重新下载（旧文件清理）。

## 8. 开放问题

- 托管源终局（HF vs GitHub Releases vs 魔搭/CDN）：P2 先 GitHub Releases 起步（免凭据依赖），分发源做成可配置，后续由所有者决定是否迁移。
