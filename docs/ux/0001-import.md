# 体验 0001：导入与增量扫描

- 状态：已评审（所有者 2026-09-04 授权连续作业，视为批准冻结）
- 关联规格：`docs/spec/0001-import.md`
- 最后更新：2026-09-04

## 1. 延迟预算（关键路径，总表见 `latency-budget.md`）

| 交互 | 预算 |
| :--- | :--- |
| 点击「选择照片文件夹」→ 选择器打开 | < 300ms |
| 选择后 → 进度条出现并开始计数 | < 500ms |
| 进度事件 → UI 数字更新 | < 100ms |
| 导入吞吐 | 批量解码 > 50 张/s（桌面 CPU，一次性验收） |

## 2. 状态矩阵（体验视角）

- 加载中：进度条为不确定总数前的细长骨架 → 枚举完成后变为确定进度；数字用等宽数字避免跳动。
- 部分成功：完成 toast 保留 6s；「N 个文件无法导入」为常驻入口（浏览页顶部横幅，可关闭）。
- 暂停：按钮变「继续」，进度条保持且呼吸动画停止；绝不出现假死。

## 3. 文案

- 空态标题："你的照片，值得被找到"；副文案："选择照片文件夹，MiaoMory 自动整理成可搜索的回忆。所有处理都在本机完成。"
- 按钮：「选择照片文件夹」/「暂停」/「继续」/「重试失败的 N 个」
- 进度："正在导入 128 / 1,024 · 预计还需 2 分钟"
- 失败项原因（中文，无裸技术词）："照片文件损坏，无法读取" / "文件不存在或已被移动" / "磁盘空间不足"

## 4. 键盘与无障碍

- 空态：Tab 可达按钮，Enter 触发；进度条 `role="progressbar"` 带 `aria-valuenow/max`。
- 暂停/继续按钮焦点可见；Esc 无操作（不取消导入，防误触；取消入口在进度条右侧次要按钮「停止」并需确认）。

## 5. 测量方法

- tracing span：`import.scan` / `import.hash` / `import.decode` / `import.thumb` / `import.persist` 各阶段耗时与吞吐，日志落盘。
- 一次性验收（ADR-0004）：用项目所有者真实照片集（≥500 张，含 HEIC）人工记录吞吐与 ETA 准确度，结果回填 `latency-budget.md`。
