# 用户旅程：现状全流程（如实记录，含缺陷）

- 状态：现行（描述 2026-09-06 时点 main 分支的真实行为，**不美化**，供所有者逐屏纠错）
- 维护者：ZCode（AI 代理）
- 对应技术文档：`docs/developers/06-import-and-indexing.md`
- 最后更新：2026-09-06

> 每一站回答三个问题：**看到什么 / 能做什么 / 背后发生什么**，并如实标注「缺陷」。编号 U1~U8 与技术文档 D1~D8 对应。

## 站 1：双击启动

| | 内容 |
| :--- | :--- |
| 看到什么 | 约 1 秒内出窗口：左上「MiaoMory」标题、右上「设置」按钮，其余空白（背景色为米白 token） |
| 能做什么 | 打开设置、关闭窗口 |
| 背后发生什么 | 解析数据布局（ADR-0011 四级）→ 初始化日志 → 检查模型状态 → **模型缺失即自动后台下载**（PR #5）→ 查询库中是否有照片 |

**缺陷**：U1｜启动后 1~3 秒内没有任何"正在准备"的指示，若模型自动下载已开始，横幅会出现——但空态页其余部分是纯空白，没有骨架或品牌感，观感像"没加载完"。

## 站 2：空态引导（库里没有照片时）

| | 内容 |
| :--- | :--- |
| 看到什么 | 居中大标题「你的照片，值得被找到」+ 一行说明「选择照片文件夹，MiaoMory 自动整理成可搜索的回忆。所有处理都在本机完成。」+ 青色主按钮「选择照片文件夹」 |
| 能做什么 | 点按钮选文件夹；Esc 无作用（无浮层）；Tab 可达按钮 |
| 背后发生什么 | 纯静态页；模型下载横幅若有则显示在其上方 |

**缺陷**：U2｜没有说明三件事：① 导入要多久/会不会卡电脑；② 模型正在下载及它的作用；③ 原图不会被移动复制。用户对"点下去会发生什么"零预期——这正是所有者产生"是不是对我的文件做了恶心操作"怀疑的根源。

## 站 3：选择文件夹

| | 内容 |
| :--- | :--- |
| 看到什么 | 系统原生目录选择对话框 |
| 能做什么 | 选一个文件夹；取消 |
| 背后发生什么 | 递归枚举支持的图片（JPEG/PNG/WebP/HEIC），按路径排序切成 32 张一批开始导入；`import_folder` 立即返回 job id，界面切到浏览态 |

**缺陷**：U3｜选错文件夹没有"预计 N 张文件"的确认步骤，直接开跑；也没有排除规则（如 ` node_modules`、回收站）的说明。

## 站 4：导入中

| | 内容 |
| :--- | :--- |
| 看到什么 | 顶部进度条：「正在导入 x / N · 失败 f · 剩余约 X 分钟」+ 暂停/停止按钮；下方是**时间轴网格——但它不增长** |
| 能做什么 | 暂停/恢复/停止（停止已处理部分保留）；切到设置；**没法看到正在导入的照片长什么样** |
| 背后发生什么 | rayon 全核并行：读盘 → 哈希 → 解码 → 缩略图 → 逐张落库（每张落库即可查）；每张完成发一次进度事件 |

**缺陷**（这是被质询最狠的一站）：
- U4｜**导入中网格不刷新**：数据每张落库，但前端只在开始/结束各刷新一次，用户全程盯着空网格 → 感知"卡死"（对应技术缺陷 D2，UX 侧最高优先级）。
- U5｜**全核饱和**：导入时机器明显卡（D1），且 UI 无任何"这会吃满 CPU，预计 X 分钟"的事先告知或降速选项。
- U6｜**零"智能感"**：模型即便就绪，嵌入也是后台静默跑，导入界面不出现"正在学习你的照片"之类的状态；模型未就绪时更是纯 CPU 劳作、没有任何 AI 相关反馈（D3）。

## 站 5：浏览（时间轴）

| | 内容 |
| :--- | :--- |
| 看到什么 | 按年份分组的缩略图网格（虚拟滚动），右上「导入文件夹」按钮可再导；搜索框置顶 |
| 能做什么 | 滚动浏览；点缩略图进 Lightbox；再导入；搜索 |
| 背后发生什么 | `list_timeline` keyset 分页按拍摄时间倒序；缩略图经 asset protocol 从本地 thumbs 读取 |

**缺陷**：U7｜导入刚结束时若照片的拍摄时间缺失（回落 mtime=0），会归入 1970 分组沉底，看起来像"照片丢了"（实际在最后）；无年份锚点快速跳转。

## 站 6：Lightbox 预览

| | 内容 |
| :--- | :--- |
| 看到什么 | 原图全屏 + 左右切换；底部删除按钮 |
| 能做什么 | ←/→ 切换、Esc 关闭、Space 缩放、Delete 删除（有确认）；显示的是**原图**（asset protocol 读原路径） |
| 背后发生什么 | `get_asset_image` 返回原文件绝对路径；删除只删索引与缩略图记录，永不碰原文件 |

**缺陷**：U8｜删除确认文案没有强调"原文件安全"这一用户最关心的点；无旋转/缩放手势。

## 站 7：搜索

| | 内容 |
| :--- | :--- |
| 看到什么 | 搜索框（模型就绪）/ 模型引导块（缺失或下载失败时）+ 下载进度横幅；输入后有结果网格（命中徽标：语义/文件名），支持年份与类型过滤 |
| 能做什么 | 中文自然语言搜索（如「海边的日落」）、文件名片段搜索、按年/类型过滤、点结果进 Lightbox |
| 背后发生什么 | 查询词过文本塔（毫秒级）→ sqlite-vec KNN + FTS5 双流 → RRF 融合；防抖 150ms，键入即搜 |

**缺陷**：U9｜搜索结果没有"为什么是这些结果"的解释文案（徽标太小）；空结果页建议词固定两条；无搜索历史。

## 站 8：设置

| | 内容 |
| :--- | :--- |
| 看到什么 | 数据位置对话框：模式徽标（口袋式/标准）、数据文件夹/索引/模型路径、「打开数据文件夹」「更改数据位置…」 |
| 能做什么 | 查看、打开、更改数据位置（重启生效）；Esc 关闭 |
| 背后发生什么 | `data_info` 读布局快照；更改写 `config.data_dir` |

**缺陷**：U10｜设置里只有"数据位置"一项——没有导入并行度/降速开关（对应 D1）、没有模型重新下载入口、没有"打开失败清单"入口（失败列表只能在导入完成横幅点「知道了」之前看到）。

## 打磨候选（仅列出，等所有者裁决后进 spec）

1. **U4 导入实时预览**（最高优先）：每 chunk 完成通知前端增量刷新——数据层已就绪，纯前端工作
2. **U5+U10 导入资源策略**：并行度滑杆/「后台模式」开关 + 空态页明示"会吃满 CPU 约 X 分钟"
3. **U2 空态页信息补全**：三条承诺写明白（原图只读/本机处理/模型用途），配当前模型下载状态
4. **U6 智能感**：嵌入进度卡（"正在学习你的照片 128/512"）在浏览态常驻直到补齐
5. U7 1970 分组问题：mtime=0 的照片归入"未知时间"独立分组而非 1970
6. U8/U9 轻量打磨：删除文案强调原图安全、结果解释悬浮提示
