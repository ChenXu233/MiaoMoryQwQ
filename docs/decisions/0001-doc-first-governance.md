# ADR-0001：规范先行治理

- 状态：Accepted
- 日期：2026-09-04
- 决策者：项目所有者
- 相关：`AGENT.md`、`docs/README.md`

## 背景

项目处于启动阶段，代码尚未初始化。历史讨论表明：决策散落在对话中会导致实现漂移；需要一套文档体系让人类协作者与 AI 编码代理对齐，并让决策可追溯。

## 决策

我们决定**规范先行**：

1. `AGENT.md` 为项目规范最高事实源，冲突时以它为准并修正冲突文档。
2. `docs/` 分六类：白皮书 / decisions（ADR）/ spec（功能规格）/ ux（体验规格）/ developers / users，各设 README 定义标准。
3. 任何设计、范围或依赖变更：先更新文档，再动代码；PR 必须包含文档更新。
4. ADR 历史不可改写，修订走 supersede。
5. 文档索引登记制：`docs/README.md` 与文档同步变更。
6. 文档头部含"状态/维护者/最后更新"三元组；数字必须实测或标注"待基准"。

## 后果

### 积极

- 决策可追溯，新参与者（含 AI）可快速对齐
- 变更成本前置到文档阶段，实现期返工少
- 模板化控制文档数量，避免文档膨胀

### 消极 / 需关注

- 文档维护开销；需克制"为写而写"，空文档不建

## 备选方案

| 方案 | 结论 | 原因 |
| :--- | :--- | :--- |
| 零治理即兴开发 | 否 | 多轮讨论已证明决策易漂移 |
| 集中式 wiki | 否 | 无法随仓库版本化、无法在 PR 中同行评审 |
