# ADR-0010：验证策略调整——TDD + 手工验收、e2e 延后、模型基准推迟

- 状态：Proposed
- 日期：2026-09-04
- 决策者：项目所有者（待批）
- 相关：ADR-0004、ADR-0006、ADR-0007；`AGENT.md` §7、§8；白皮书 §3.4、§6.2

## 背景

MVP 启动评审中，项目所有者对验证策略作出三点裁定：① 前端与检索质量由所有者本人照片集**手工验证**，AI 代理不代做质量测试；② e2e 自动化（tauri-driver/Playwright）在 MVP 阶段延后，开发以 **TDD**（单元测试先行）保证质量；③ ADR-0006 的三候选模型**一次性基准推迟**，P2 直接采用现成可用的 ONNX 模型先跑通核心体验，"做更实际的活"。原 ADR-0004/0006/0007 已 Accepted 不可改写，故以本 ADR 记录调整。

## 决策

我们决定：

1. **验证方式**：Rust 侧（core/store/pipeline/embed 逻辑与纯函数）一律 TDD——先写失败测试再实现；UI 与检索质量不走自动化测试，由项目所有者按**手工验证清单**（MVP 计划 §5/§6 各一份）亲自执行。
2. **e2e 延后**：tauri-driver/Playwright 自动化与常驻 CI e2e 不在 MVP 范围；恢复时机为 alpha 之后视回归痛点决定。CI 常驻内容收缩为：格式 / lint / clippy / tsc / 单元测试 / specta 契约生成一致性 / 三平台构建矩阵。
3. **模型基准推迟与临时选型**：ADR-0006 的一次性基准推迟（候选池 jina-clip-v2 / BGE-Visualized / Chinese-CLIP 与"中文硬约束"保留不变）；P2 临时选用 **Chinese-CLIP ViT-B/16**（MIT 许可、官方 ONNX 导出路径、188M 参数 / 512 维）直接跑通语义检索。
4. **质量把关与回退路径**：临时模型的检索质量由所有者本人照片集 + 自拟中文查询词逐条手工验收；**不达标即提前恢复 ADR-0006 正式基准流程**，届时更换模型必须给出索引重建迁移策略。
5. 一次性延迟实测（文本编码 / KNN / 首屏）保留，结果记录 `docs/ux/latency-budget.md`，数字只来自实测（ADR-0004 原则不变）。

## 后果

### 积极

- 开发节奏更实际：先跑通"导入 → 搜索"核心闭环，把选型决策推迟到有真实体验数据之后
- 质量责任清晰：确定性逻辑由 TDD 保障，体验与检索质量由最了解数据的所有者裁定
- CI 时间与维护成本进一步降低

### 消极 / 需关注

- 无端到端回归防线，UI 回归依赖手工清单的自律执行
- Chinese-CLIP ViT-B/16 质量上限未经理性基准验证，存在返工风险（已设回退路径）
- 512 维临时维度意味着 P2 的 `vec_assets` 迁移在正式选型后可能需要重建索引

## 备选方案

| 方案 | 结论 | 原因 |
| :--- | :--- | :--- |
| 维持 ADR-0004/0006/0007 原验证节奏（先基准后开发、CI 带 e2e） | 否 | 所有者裁定：推迟基准、先做实际的活；e2e 在个人项目早期成本大于收益 |
| 推迟基准但临时选 jina-clip-v2 | 否 | CC-BY-NC 非商业许可 + ~1.7GB 下载体积，与"首次模型下载体验"目标冲突 |
| 无临时模型，P2 空窗 | 否 | 语义搜索是 MVP 核心体验，不可整体推迟 |

## 备注

触发重审条件：① P2 手工验收不达标；② 应用准备商用/分发（临时模型的许可与性能需正式基准确认）；③ 候选池出现新的强候选模型。
