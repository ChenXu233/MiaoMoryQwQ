# ADR-0004：性能验证与 CI 策略

- 状态：Accepted
- 日期：2026-09-04
- 决策者：项目所有者
- 相关：`docs/ux/latency-budget.md`、白皮书 §6

## 背景

评审确认：语义检索性能是 sqlite-vec 的职责，不是我们的核心设计；在 CI 常驻万级合成照片 bench 不实际且浪费 CI 时间；种子数据生成器亦被评估为不实际（测试数据可由项目所有者人工提供）。

## 决策

我们决定：

1. **CI 不跑常驻语义检索/万级合成 bench**。sqlite-vec 检索性能做一次性人工验收（目标规模 ≤5 万向量），结果记录后归档。
2. **模型推理速度做一次性人工基准**（批量吞吐、单 query 延迟、量化后体积），结果记录 `docs/ux/latency-budget.md`；不做每次 CI 检查。
3. **升级触发重验**：模型 / ORT / sqlite-vec / Tauri 大版本变更时，重跑对应的一次性基准。
4. **种子数据生成器延后**；e2e 与基准所用数据由项目所有者人工提供（真实照片），不生成合成图片。
5. **CI 常驻内容**：格式 / lint / clippy / tsc / 单元测试 / specta 契约生成一致性 / e2e 体验流程（小规模固定人工数据集）。

## 后果

### 积极

- CI 时间与维护成本低，聚焦确定性检查
- 关注点回归自身代码（契约开销、N+1、解码管线）

### 消极 / 需关注

- 无持续性能回归检测；缓解：升级触发重验清单 + tracing 日志 + 开发版性能浮层

## 备选方案

| 方案 | 结论 | 原因 |
| :--- | :--- | :--- |
| 常驻 10k 合成照片 bench | 否 | 语义检索非我方核心设计，浪费 CI 资源 |
| 每次 CI 检查模型速度 | 否 | 一次性检查即可，反复跑无增量价值 |
| 合成种子数据生成器 | 延后 | 不实际；测试数据人工提供 |
