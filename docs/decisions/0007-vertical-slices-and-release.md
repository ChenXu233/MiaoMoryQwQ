# ADR-0007：垂直切片与发布节奏

- 状态：Accepted
- 日期：2026-09-04
- 决策者：项目所有者
- 相关：`AGENT.md` §7

## 背景

需要一条既能持续交付、又能把体验打磨前置的开发节奏。

## 决策

我们决定按垂直切片推进，每片都可发布、可体验：

| 阶段 | 内容 | 体验验收 |
| :--- | :--- | :--- |
| P0 | workspace 骨架 + specta 契约 + 更新器 + CI | 类型安全 IPC 成为日常 |
| P1 | 导入 → 缩略图 → 时间轴浏览（无 AI） | 进度可暂停/恢复；坏文件隔离 |
| P2 | 模型下载 → 嵌入 → 中文语义搜索 | 状态矩阵齐全；延迟预算达标 |
| P3 | FTS/过滤/RRF 融合 + 键盘操作 + 打磨 | 发布首个 alpha |

切片 DoD：文档先行（规格已写并登记）→ 实现（命令/查询 + pipeline 阶段 + UI + 单测）→ e2e 至少一条主链路 → lint/clippy/tsc/契约一致 → 涉及模型或索引变更时一次性基准已记录。

发布：alpha 起每周构建 + 自动更新器（首日接入）；tracing 日志落盘 + 开发版性能浮层。

## 后果

### 积极

- 每阶段产出可运行、可反馈的版本，体验问题提前暴露
- 风险前置：模型/索引风险在 P2 单点验证

### 消极 / 需关注

- 文档与实现同步的要求让节奏略慢；缓解：模板化 + 文档先行
