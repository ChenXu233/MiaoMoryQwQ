# 02 垂直切片工作流与 DoD

状态：现行
维护者：项目所有者
最后更新：2026-09-04

## 什么

P0 → P3 每个切片从开工到合入的固定流程。

## 为什么

文档先行 + TDD + 质量门是 AGENT.md 铁律；固定流程让"每一片都可发布、可体验"。

## 怎么做

1. **分支**：`feature/<slice>` 从 main 拉出；一个 PR 一个切片。
2. **文档先行**：spec/ux 规格先提交（编号同号对应，登记两级索引）。
3. **TDD**：core/store/pipeline 逻辑先写失败测试再实现；UI 走手工验证清单（ADR-0010）。
4. **提交**：Conventional Commits，一个提交一件事。
5. **PR 合入**：CI 四项检查（质量门 + 三平台构建）全绿后 squash 合入（保护规则强制线性历史）。
6. **收尾**：规格状态翻「已实现」；涉及模型/索引的切片把实测数字回填 `docs/ux/latency-budget.md`；手工验证清单交所有者执行。

切片映射：P0 骨架（已完成）→ P1 导入与浏览 → P2 模型与语义搜索 → P3 融合检索与 alpha 发布。
