# 04 测试策略与手工数据集约定

状态：现行
维护者：项目所有者
最后更新：2026-09-04

## 什么

Rust 侧自动化测试（TDD）与 UI/检索质量手工验证的分工与数据约定（ADR-0010）。

## 为什么

确定性逻辑交给测试保证回归；体验与检索质量由最了解数据的所有者裁定。e2e 自动化延后。

## 怎么做

### 自动化（随代码提交，CI 必跑）

- `mm-core`：纯函数（RRF 融合、方向校正矩阵、量化）与 trait mock。
- `mm-store`：迁移正确性（逐版本 schema 断言）、去重唯一约束、查询分页、事务双写原子性（P2 起）。
- `mm-pipeline`：scan 过滤、坏文件隔离、暂停/恢复状态机、进度事件节流；用临时目录构造小样本，不依赖任何外部数据。
- `mm-embed`（P2）：预处理数值断言（golden 小图）、文本分词对齐；推理本身不进 CI（无模型文件），本地冒烟。

### 手工验证清单（所有者执行，每切片一份，见对应 spec §验收）

- 数据约定：个人照片集**永不入库**、永不上传；仅本地验证。
- 建议样本构成：≥500 张混合 JPEG/PNG/WebP + 若干 HEIC + 1~2 个故意损坏文件。
- P2 额外：10~20 条自拟中文查询词，逐条验收命中质量（不达标 → 触发 ADR-0006 正式基准）。

### 一次性性能实测（ADR-0004）

切片合入后，按 `docs/ux/NNNN-*.md` §测量方法执行一次，数字回填 `latency-budget.md`；模型/ORT/sqlite-vec/Tauri 大版本升级时重验。
